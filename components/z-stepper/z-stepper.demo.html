z-stepper

Zoé entoure un <input type="number"> natif au lieu de le remplacer : l'input garde le formulaire, les flèches ↑ ↓, la saisie et les bornes ; z-stepper ajoute « − » et « + ». Changez la peau en haut à droite — tout suit.

1 · La forme canonique — un input dedans

<z-stepper aria-label="Quantité">
  <input type="number" name="qty" value="3" min="0" max="9" step="1">
</z-stepper>

L'input est la source de vérité : valeur, bornes et pas sont lus dessus. Les deux boutons sont peints (::before / ::after), jamais injectés. Cliquez au centre et tapez : c'est le champ natif.

2 · Les bornes — at-min · at-max

Au plancher
Au plafond
Sans bornes
Par demi

À la borne, le bouton mort se grise : le composant pose at-min / at-max sur l'hôte et le CSS les peint. Sans min/max, rien ne se grise jamais. Un libellé visible + aria-labelledby nomme le groupe.

3 · Coupé

Stepper désactivé
Input désactivé

disabled sur le stepper coupe les zones et grise l'ensemble ; disabled sur l'input bloque la frappe (et grise les deux boutons aussi). Un <fieldset disabled> fait les deux.

4 · Les événements partent de l'input

Invités 
stepper.addEventListener("input", () => echo.textContent = stepper.value);  // bulle depuis l'input
stepper.stepUp();          // le même chemin que le « + » : borné, puis input + change

Valeur : — · dernier événement : —

Un cran déclenche input puis change sur l'input, qui bulle : écoutez le stepper ou le formulaire, tout écouteur natif suit. Déjà à la borne : rien ne part.
