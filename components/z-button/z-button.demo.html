z-button

Un bouton bâti sur z-element : il hérite tous les états. Survolez, pressez, lâchez dehors (releaseOut), naviguez au Tab puis Entrée. Changez la peau en haut à droite — tout suit.

1 · Les états, posés à la main

Envoyer Chargement… Erreur Validé Indisponible

Un mot dans le HTML, et le composant sait quoi montrer. Ce sont les états de z-element — z-button n'en écrit aucun.

2 · Le fond est une pièce : il respire, le texte ne bouge pas

Le fond respire ★ Favori 
/* la pièce `background` est le ::before — une peau l'anime sans toucher au texte */
z-button.respire::before { animation: respire 2.4s var(--z-ease) infinite; }
@keyframes respire { 50% { scale: 1.06 1.14; } }

Rien à écrire dans le HTML : les pièces sont peintes, pas posées. Le fond (::before) a sa vie, le texte reste en place. Une icône ? C'est du contenu : vous l'écrivez, elle prend sa place dans la ligne.

3 · Trois tailles, trois tons, une largeur

xs s défaut l xl
main complement soft
pleine largeur

Un seul réglage à l'intérieur — la taille du texte. Tout le reste est en em, donc tout suit : le padding, le filet, le rayon, la case. Les facteurs appartiennent à la peau, pas au composant.

4 · La séquence — loading → success

Envoyer pour de vrai au repos 
btn.setState("loading");
// …à la fin de l'envoi :
btn.setState("loading", false);
btn.setState("success");     // le CSS sait qu'on ARRIVE de loading : :state(success):state(from-loading)

Cliquez : il part en chargement, puis bascule en validé. Le socle pose au passage un état de provenance — une séquence est une combinaison, pas une animation écrite à la main.

6 · Sur téléphone : le doigt a sa place

xs × −
Voir la zone du doigt Tapez JUSTE à côté d'un bouton, dans le pointillé.

Un bouton xs fait à peine 30 px de haut : injouable au pouce. Chaque élément interactif reçoit du socle une zone de contact invisible d'au moins 44 px, centrée sur lui, qui déborde. Rien à écrire. La peau fixe le minimum ; montez le curseur et la zone grandit, le dessin ne bouge pas.
