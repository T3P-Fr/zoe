z-field

Un champ de formulaire autour d'un contrôle natif : le navigateur garde le clavier, l'autocomplétion et la validation ; Zoé relie le label, l'aide et l'erreur, et rend les états visibles. Rien remplacé, rien injecté. Changez la peau en haut à droite — tout suit.

1 · Le champ canonique — tapez, puis sortez du champ

Nous ne la partagerons jamais.

Le champ ne juge jamais pendant la première frappe. Quittez-le : s'il est invalide, le message du navigateur s'écrit dans [part=error] laissé vide ; corrigez, il s'efface en direct. Valide et non vide : success.

2 · Les trois contrôles que le champ sait envelopper

Minuscules, chiffres et _ — trois caractères au moins. Facultatif.

required, minlength, pattern restent sur le contrôle : une seule source. Le champ lit validity, il ne recalcule rien.

3 · Le compteur — counter, écrit en CSS pur

Soyez bref.

Le champ pose deux nombres sur l'hôte (--z-field__length, --z-field__max) ; le CSS les écrit avec counter() au bout de l'aide — aucun nœud, aucun texte posé par le JS.

4 · Ce que filled permet — un label flottant, sans JS

Le label est posé dans le champ au repos et remonte sur le filet au focus ou dès qu'il y a une valeur (:state(filled)). Quelques lignes de CSS d'auteur — voir le <style> de cette page.

5 · Les états posés à la main

Une erreur venue du serveur ? Posez error et votre texte dans [part=error] : le champ ne le touche pas. disabled descend sur le contrôle.

Rien envoyé pour l'instant.

La validation est celle du navigateur : à la soumission, chaque champ refusé passe en error, écrit son message (la bulle native est retenue), et le focus va au premier. Le reset ramène tout au repos.

const field = document.querySelector("z-field");
field.control;            // → le <input> natif
field.valid;              // → la validité native, à l'instant
field.validate();         // juge maintenant : pose error/success, écrit le message
field.addEventListener("change", () => field.valid);   // le change du contrôle bulle, intact
