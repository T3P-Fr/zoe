Zoé — le socle

Tu écris le sens. Zoé fait le reste. Trois mots dans ton HTML, et tu obtiens un élément complet — beau, animé, cliquable, indexable. Cette page en est la preuve : elle est écrite en HTML nu, et c'est la peau qui l'habille.

La promesse, en une ligne

<z-button>Envoyer</z-button>

Pas de <div> de structure, pas de JavaScript à câbler. Le bouton réagit (survol, appui, focus, chargement), il part dans un <form>, il se laisse habiller par n'importe quelle peau. Tu n'as écrit que le sens.

Le partage : HTML · CSS · Zoé

Toute Zoé tient dans cette répartition. Chacun son rôle, jamais l'un dans l'autre :

La couchePorte…Lu par Google ?
HTMLle sens (le texte, le rôle)oui
CSSle dessin (les couches, le mouvement)non
Zoéle vivant (les états), pose les couches, veille—

Le HTML est pour Google. Le CSS est pour l'œil. Zoé fait tenir les deux.

Le SEO est un acquis, pas un combat

Le contenu reste natif : un titre est un <h1>, un lien un <a href>, un paragraphe un <p>. Google les lit tout de suite, sans JavaScript — c'est le Light DOM. La peau les habille, elle ne les remplace jamais.

Seuls les widgets — boutons, curseurs, onglets, ce qui n'a aucune valeur pour l'index — deviennent des z-*. La règle tient en une bascule :

Lu par Google → natif, habillé par la peau. Cliqué → z-*.

Les couches : le nom dit la place

Sous un composant, le dessin est fait de couches — des <div> muets, nommés par leur rôle. Et le rôle porte sa position :

  • .z-background → au fond
  • .z-label → le contenu, au milieu
  • .z-hitArea → devant, capte le geste

Tu n'écris jamais ces couches dans le HTML. C'est le CSS qui les réclame : dès qu'une règle vise .z-background, Zoé la lit, crée la couche et la pose à sa place. Tu inventes un rôle à toi — .z-cacahuete ? Elle le crée aussi, mais en neutre, et te dit gentiment de lui donner sa place. Aucun plafond.

Un exemple qui bouge — un carré derrière, une icône qui rebondit à l'apparition, et en chargement le texte s'efface pour ne laisser que l'icône. Tout est en CSS ; le HTML n'a pas bougé d'un mot : 

z-button > .z-background     { background: var(--z-accent); border-radius: 8px; }
z-button > .z-icon           { content: "✈"; z-index: 4; }

z-button:state(enter) > .z-icon   { animation: boing .55s var(--z-ease-spring); }
z-button:state(loading) > .z-label { opacity: 0; }        /* le texte part */
z-button:state(loading) > .z-icon  { animation: spin 1s linear infinite; }

Ce que le socle garantit

Sur cette base, tu composes des éléments :

  • visuels — les couches et le CSS dessinent tout ;
  • animés — les états (:state(over), :state(loading)…) et les mouvements partagés, chaque pièce à son horloge ;
  • interconnectés — le z-channel : un élément pilote une valeur qui traverse jusqu'à un autre. Un curseur repeint une carte à l'autre bout de la page, sans une ligne de JavaScript de câblage.

Le pacte

Cette base est figée. On ne la re-dessine pas — on compose par-dessus. C'est le deal : le socle porte tout ce que tu imagines, à condition qu'on le laisse tranquille et qu'on bâtisse dessus plutôt que de le refaire.

Sous le capot, Zoé tient en peu de fichiers — CSS : tokens (les valeurs) · layers (les places) · motion (les mouvements). JS : z-element (le vivant) · zoé-layers (les couches) · zoé-console (la veille). Chaque composant, lui, reste maigre : il dit seulement « je suis un bouton ».
