z-inview — ce qui est à l'écran, dit au CSS

Enveloppe, et l'apparition s'écrit en CSS. Cette page ne contient pas une ligne de JS. Défilez jusqu'en bas — puis remontez : c'est là qu'on voit la différence entre « une fois » et « à chaque passage ».

<z-inview margin="-80px" class="entre">…</z-inview>

.entre {
  opacity: var(--z-inview__seen);                            /* 1 une fois vu, à jamais */
  translate: 0 calc((1 - var(--z-inview__seen)) * 24px);
  transition: opacity .7s ease, translate .7s cubic-bezier(.2, .8, .2, 1);
}

/* la cascade n'est pas un outil de plus : un délai par enfant, et c'est tout */
.cascade > * { transition-delay: calc(var(--i) * 90ms); }

--z-inview__seen monte à 1 la première fois et n'en redescend jamais — c'est ce qui évite le tournis quand on remonte. La cascade n'est pas un outil de plus : juste un transition-delay par enfant. margin="-80px" attend qu'ils soient bien entrés.

2 · il va et il vient — __in, à chaque passage

je pars quand je sors, je reviens quand j'entre
le même geste, l'autre nombre
 
.vaEtVient {
  opacity: var(--z-inview__in);              /* __in au lieu de __seen : voilà tout */
  scale: calc(.9 + var(--z-inview__in) * .1);
  transition: opacity .5s ease, scale .5s ease;
}

__in retombe à 0 en sortant : l'auteur choisit lequel des deux nombres il lit, et c'est tout le réglage. Aucun attribut « once », aucune option.

3 · la traversée — __cross, quand ratio sature

le décor dérive, l'image se colore
__in
__ratio
__seen
__cross 
/* __cross continue de monter quand __ratio a saturé à 1 */
.traversee i { translate: 0 calc(var(--z-inview__cross) * -120px); }   /* le décor dérive */
.traversee b { filter: grayscale(calc(1 - var(--z-inview__cross))); }  /* elle se colore */

Regardez les quatre jauges pendant que vous défilez : __ratio monte, puis sature à 1 dès que le bloc tient à l'écran — alors que __cross continue jusqu'au bout. C'est lui qu'il faut pour un décor qui glisse pendant toute la traversée.
